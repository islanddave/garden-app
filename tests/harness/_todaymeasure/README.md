# `_todaymeasure` — the Today page's measurement instrument

The only instrument that measures the Today page in real Chrome. Built 2026-09-08 on a lane branch
that never merged (`lane-layoutgate-20260908`), ported to dev and re-pointed at Dave's handset on
2026-09-24 (V5-TODAYSHAPE-001, OPS-TODAYVIEWPORTWIDTH-001). jsdom cannot see layout: clipping
CareNeeded's row panel to `height:0` hid the whole care list and 9,239 of 9,241 unit tests still
passed. This directory and the gate built on it are how that shape gets caught.

## What is here

| file | what it is |
|---|---|
| `../todaymeasure.html` + `../todaymeasure.jsx` | mounts the **real** `src/pages/Today.jsx` inside the **real** `AuthProvider` and `MemoryRouter`. Nothing under `src/` is re-implemented; only `window.fetch` is stubbed, at the wire. The html pins the clock (inline, ahead of every module). |
| `dump-prod.mjs` | regenerates the fixtures from live prod, **read-only** (see `bands-notes.md`). Writes RAW dumps to `out/raw/` (gitignored). |
| `*.json` (except the budget) | the fixtures — dumped 2026-09-24 and **scrubbed** (below). Provenance per file: `bands-notes.md`. |
| `busyfull-grafts.json` | real payload fragments from other prod days (and one engine-generated synthetic) that build the `busyfull` state. |
| `storage-grafts.json` | real prod rows, one field moved each (provenance per key), that build the `storage` state: a sweet-potato planting's status, and the stored jars' use-by status. |
| `today-shape-budget.json` | **the baseline**, generated by `npm run gate:today-shape:record`. Every number in it is a real `getBoundingClientRect` / `Range.getClientRects` reading. |
| `drive.mjs` | the **recorder**. Drives real headless Chrome at a CDP-emulated 426x836 @ DPR 3 and writes a full capture + screenshots (badge shows the page's own `innerWidth`) to `out/`. Asserts nothing; it records. |
| `analyse.py` | turns a capture into the section / whitespace / type / control tables. |

The **gate** built on top of it is `scripts/layout-gate/today-shape.mjs` (`npm run gate:today-shape`).
The recorder and the gate are deliberately different programs: the recorder characterises and the
gate refuses, and conflating them is how a gate ends up re-recording its own baseline to go green.

## States

| state | what it is |
|---|---|
| `busy` | today's real plan (the 2026-09-24 10:00 ET run) and today's real bands. The honest current screen. |
| `busyfull` | `busy` PLUS every conditional line Today can show — frost line, weather cue, drought line and dry list, leaf wetness, rain note — grafted from the latest real prod day each occurred, and the compose band from a real batch on a moved clock. |
| `quiet` | a plan exists, every list in it is drained, no conditional line. "The engine ran and there is nothing to do." |
| `noplan` | `has_plan: false` — the engine has not run for this user today. |
| `storage` | `quiet` one week on: clock pinned to 10:30 ET on 2026-10-01 (`../todaymeasure.html`) and the plan re-dated to that morning, so the two regions no 2026-09-24 instant can show render — `StorageDeadlineAlert` (the sweet-potato check window opens 09-28) and `PutUpUseSoonBand` (jars in their use-by window). Added 2026-09-25. |
| `busyhh` | `busy` with the household lens open. Recorder only; not in the gate budget. |

## The fixtures are scrubbed, and exactly how

`scripts/layout-gate/todayshape-fixture-scrub.mjs` is the one-way transform from a raw dump to a
trackable fixture. It rewrites two classes and **nothing else**:

- every Clerk-sub-shaped id → a pseudonym assigned by frequency across the whole corpus. The most
  frequent becomes `harness_user`, the id the harness Clerk stub serves — not cosmetic, because
  `ComposeHarvestBand` scopes its batch to the **viewer**, so a fixture whose `created_by` is anything
  else renders a 0px band and the instrument silently measures less page than it claims to. The
  2026-09-24 dump carried only the viewer's sub (331 occurrences).
- every `lat`/`lng`/`lon`/`latitude`/`longitude` key → the single declared synthetic site
  (39.8283 / −98.5795, the geographic centre of the contiguous US). Rounding a residence coordinate
  is not scrubbing it.

**Real plant names, cultivar names and location paths are deliberately kept.** They are
horticultural rather than credential-shaped, they are already throughout the repo's own tracked
tests, and they are load-bearing for what is being measured: label length drives row height,
group-header wrapping and the ellipsis in `Row`. The harness member list is first names only.

`scripts/layout-gate/todayshape-fixture-preflight.mjs` is the guard, not the scrub. It runs as step
0 of the gate and on its own (`npm run gate:today-shape:preflight`), refuses Clerk-sub-shaped ids,
live keys, JWTs, Postgres URLs, email addresses and any coordinate that is not the synthetic site,
and carries `--self-test`, which fires every matcher against a known positive built inside the file
(never sampled from the corpus it guards) and exits 1 unless all of them fire.

## The baseline, re-recorded 2026-09-25 in the pinned Roboto

Real Chrome, CDP-emulated 426x836 `mobile:true` @ DPR 3 (page self-reports it), clock pinned to
`2026-09-24T14:30Z` (10:30 ET), timezone `America/New_York`, Open-Meteo stubbed at the wire, and
the text laid out in `@fontsource/roboto@5.3.0` by `../robotoPin.js` — the face Dave's
Android renders, and the same glyphs on the Mac and on CI's runner. That is what lets the gate run
in CI (V5-TODAYSHAPECI-001): the 2026-09-24 baseline was San Francisco geometry from this Mac.

| state | scrollHeight | content ends | ink % | care rows | groups | expanded | Moist | Show more | controls | 1st control |
|---|---:|---:|---:|---:|---:|---:|---:|---:|---:|---:|
| `busyfull` | **6,620px** (7.92 viewports) | y=6,580 | 54.5 | 66 | 9 | 1 | 20 | 1 | 285 | y=666 |
| `busy` | 6,118px (7.32) | y=6,078 | 54.4 | 66 | 9 | 1 | 20 | 1 | 282 | y=454 |
| `quiet` | 836px (1.00) | y=508 | 29.7 | 0 | 0 | 0 | 0 | 0 | 1 | y=476 |
| `noplan` | 836px (1.00) | y=324 | 21.3 | 0 | 0 | 0 | 0 | 0 | 1 | y=293 |
| `storage` | 1,022px (1.22) | y=965 | 56.4 | 0 | 0 | 0 | 0 | 0 | 2 | y=719 |

`storage` is measured at its own instant, 2026-10-01T14:30Z (each budget state records its clock);
the storage alert paints at y=90 (199.5px) above the weather card and the use-soon band at y=704
(230px).

The same page in San Francisco (the 2026-09-24 budget) measured 6,641 / 6,138 / 836 / 836, content
ending at 6,602 / 6,099 / 510 / 325: every count is identical, only glyph geometry moved. The budget
records the font build it was measured in, and the gate refuses to compare across builds.

Two things these numbers say about the page, read off the record rather than argued: the length cap
(V5-TODAYCAP-001) holds the lead group (Bag Area, 143 care rows) to 66 rendered rows — the 20
longest-waiting water rows (20 Moist buttons) plus 46 feed/check/protect rows, which the cap does not
touch; and on `busyfull` the four ambient weather lines push the care list down by 212px, so it
starts at y=666 of the 836px first screen instead of y=454.

### Two numbers the harness cannot see, printed anyway

The harness mounts `Today` alone. Production adds TopChrome (`BAR_H`, 52px) and BottomNav
(`BOTTOM_NAV_HEIGHT_PX`, 56px), both read from source by the gate, so only 728px of the 836px window
ever shows page content — `busyfull` is **9.24 usable-window-heights**, not 7.92. Printed on every run.

### `scrollHeight` is clamped, and the floor that is not

A document is never shorter than the viewport, so on `quiet` and `noplan` (both exactly 836px) a
scroll-height floor is **vacuous** — a completely blank page satisfies it. That is why the gate also
records `contentBottom`, the y of the last row on which anything paints (508 and 324). That is the
floor that bites on the short states.

## Re-running

```
npm run gate:today-shape                  # the gate — refuses, exits non-zero
npm run gate:today-shape:probe-nothing    # proves the gate can fire; MUST exit 1
npm run gate:today-shape:preflight:self-test && npm run gate:today-shape:preflight
npm run mutate:today-shape                # 26 real defects; each must red the gate on >=2 killers
npm run gate:today-shape:record           # re-record the baseline. ONLY on a clean tree. Never a fix.
npm run todaymeasure -- --states busy,busyfull,busyhh,quiet,noplan   # recorder + screenshots
python3 tests/harness/_todaymeasure/analyse.py tests/harness/_todaymeasure/out/measure-busy.json
```

Refreshing the fixtures (read-only against prod; select the URL by KEY NAME, never by pattern):

```
export NEON_DATABASE_URL=$(grep -m1 '^NEON_DATABASE_URL=' <garden-app checkout>/.env.local | cut -d= -f2-)
export GARDEN_HOUSEHOLD_IDS=$(aws lambda get-function-configuration --region us-east-1 \
  --function-name garden-harvests --query 'Environment.Variables.GARDEN_HOUSEHOLD_IDS' --output text)
npm run todaymeasure:dump
node scripts/layout-gate/todayshape-fixture-scrub.mjs --from tests/harness/_todaymeasure/out/raw
npm run gate:today-shape:preflight
# then move the clock pin in ../todaymeasure.html to just after the dumped plan's generated_at,
# re-record on a clean tree, and re-run the mutation matrix.
```

## Viewport

**426x836 CSS px at DPR 3 — read off Dave's handset 2026-09-24** (More → Debug & smoke →
"Viewport (CSS px)"). The gate was built at 390x844, the iPhone 12/13/14 preset, while the width was
an open question. Android's Display size setting moves the CSS width on the same hardware, so if the
phone's setting changes, re-read the row and re-point with
`GATE_VIEWPORT_W=<w> GATE_VIEWPORT_H=<h> npm run gate:today-shape:record` plus the defaults in the
gate. The budget records the viewport and the pinned clock it was captured at, and the gate refuses
a mismatch on either rather than comparing across them.
